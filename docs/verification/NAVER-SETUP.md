# NAVER 지도 — 이번 앱에 필요한 설정

기존 앱·키·URL·한도는 수정하지 않는다. 이미 이번 신규 앱 전용 Application이 있다면 다시 만들지 않는다.

공식 절차: https://guide.ncloud-docs.com/docs/application-maps-app-vpc
공개 SDK 식별자: https://navermaps.github.io/maps.js.ncp/docs/tutorial-2-Getting-Started.html

1. NCP 콘솔의 **VPC → Application Services → Maps → Application**에서 이번 새 앱 전용 Application 존재 여부를 확인한다. 기존 Claude 앱은 열어서 수정하지 않는다.
2. **Maps 대표 계정 조회**에서 무료량 적용 계정인지 확인한다. 새 계정 가입이나 대표 계정 변경은 필요하지 않으며 이번 작업에서 요청하지 않는다.
3. 새 앱을 준비할 경우 Dynamic Map만 선택한다. 이름 예시는 `jeju-codex-new`. 기존 앱의 Client ID를 복사해 사용하지 않는다. 등록 전 약관과 과금 조건을 확인한다.
4. Web 서비스 URL은 실제로 지도를 표시할 개발 페이지 주소가 확인된 뒤 최소 범위로 지정한다. 임의 Vercel 주소나 기존 서비스 도메인을 추가하지 않는다. 현재 127.0.0.1:4173은 실행 환경 내부 프리뷰 주소이며, 사용자의 브라우저 주소와 같다고 가정하지 않는다.
5. 새 앱의 Dynamic Map에서 **한도 및 알림 설정 → 한도 설정**을 열어 일/월 한도를 설정하고 **한도 초과 사용은 비허용**으로 둔다. 계정의 기존 다른 앱을 포함한 총량이 무료량 안에 들어갈 여유를 확인해야 한다. 기존 앱의 한도를 줄이거나 무료량을 앱마다 별도라고 계산하지 않는다. 여유 예산이 확인되지 않으면 지도는 로드하지 않는다.
6. Client Secret은 설정하지도 전달하지도 않는다. 공개 Client ID는 도메인·무료 조건 확인 후 실행 환경에 `VITE_NAVER_MAP_CLIENT_ID`로 등록할 후보다. 현재 앱은 이 값을 읽거나 SDK를 로드하지 않는다. 실제 값은 채팅에 쓰지 않는다.

지금 사용자에게 필요한 정보는 **이번 앱 전용 Application이 이미 있는지**, **현재 계정에 무료량이 적용되고 이번 앱에 할당할 여유가 있는지**다. 아직 없다면 설정 전 현재 상황만 알려주면 된다. 이미 완료한 설정을 반복할 필요는 없다.

지도 공개 구조 승인은 완료되었다. 콘솔 무료 자격·합산 예산·한도·브라우저 도메인과 제공자 위치 처리 검증이 마무리된 뒤에만 실제 지도 호출을 수행한다.
