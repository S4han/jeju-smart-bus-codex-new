## 명세의 불일치와 검증 계획

1. **인증 상충:** 개요 '없음' 대 요청 `serviceKey`. 현재 공식 운영 안내 또는 제공기관 답변으로 해결한다. 필요성이 확정되기 전에 무조건 키 발급을 요구하지 않는다.
2. **요청 의미:** BusArrives의 URL `route`와 요청 표/예제 `station`, BusArrived의 `station` 항목을 노선 ID로 설명하는 부분, 여러 표에서 `routeId`를 정류소번호로 적은 부분이 있다. 필드 이름만으로 의미를 고정하지 않는다.
3. **XML 예제:** `<time>`으로 열고 `</item>`으로 닫기, `calcData`/`calcDate`, `useeyn`/`useYn`, `reponse` 등의 불일치가 추출 본문에서 확인된다. 이 예제를 파싱해 성공/실패한 결과를 실제 API 품질 검증으로 취급하지 않는다. 원본의 표/예제도 필요 시 재대조한다.
4. **동일 샘플의 불일치:** Station과 Station2 예제에 같은 정류소 ID가 서로 다른 명칭/좌표로 나타난다. 명세 샘플을 정류소 ID 매핑의 정답 데이터로 사용할 수 없다.
5. **거리·좌표:** `localX/Y`는 좌표 필드 후보이나 EPSG/좌표계가 명확하지 않다. `routeDist`는 노선기점 대비 거리로 설명되지만 단위와 누적거리/방향 재시작 규칙을 검증해야 한다. `waypointOrd`로 실제 도로 궤적을 생성하지 않는다.
6. **증분·페이징:** `last`가 있지만 포함/제외 경계·시간대·삭제행 처리·최초 전체 조회 방식이 불명확하다. 응답에 페이지 필드가 있다고 문서에 없는 요청 파라미터를 임의 추가하지 않는다.
7. **시간:** 도착예정 '분'이라는 문서 근거는 확보했지만 실시간 산출시각·음수/0·누락·오래된 값 의미는 미검증. `upd`는 기초정보 수정시각이지 도착 예측 산출시각이 아니다. 첫·막차와 배차 간격으로 임의 대기시간/총 소요시간을 만들지 않는다.

## 조건 충족 후 요청 계획 구체화

TASK-001의 총 13회 상한은 유지한다. 아래는 기존 목적을 새 명세에 연결한 **조건부 후보**로 실제 허용량은 여전히 0이다.

| 목적 | 후보 | 기존 예산 안 최대 |
|---|---|---:|
| 정류소 기본 표본 | Station | 2 |
| 노선 기본 표본 | Bus | 1 |
| 노선 정차순서/방향 | StationRoutePr | 2 |
| 정류소 경유관계 대조 | StationRoutePs | 1 |
| 도착정보·산출시각/단위 | BusArrives, 필요 시 BusArriveInfo로 1회 대체 | 2 |
| 시간표 대체 가능성 | BusInfo 또는 LowBusInfo 중 목적에 맞는 1개 | 1 |

ID는 현재 정상 반환된 기본 데이터에서 확보하고 다음 요청의 일관성을 검증한다. 과거 문서 샘플만 쓰고 현재 ID 유효성이 확인되었다고 주장하지 않는다. 첫 목록 응답이 크거나 페이지가 추가로 필요하면 자동으로 전체를 순회하지 않고 예산·응답크기 제한·표본 구성을 먼저 재검토한다. 오류·타임아웃·인증/쿼터 오류 시 기존 중단 조건을 따른다.

## 남은 조건과 다음 행동

- 현재 서비스 URL/HTTPS 지원, 인증 유무와 필요 시 안전한 키 설정, 사용 신청/승인·현재 무료량/호출 제한·초과 정책을 확인한다. HTTP에 비밀키를 보내는 구조라면 그대로 진행하지 않고 안전한 대안을 검토한다.
- 제공자 실패 본문 로그의 실제 수집 항목·보관기간·키 마스킹을 확인한다. 사용자 좌표 없이 공공 ID만으로 버스 데이터 검증을 수행할 수 있는 조건을 별도로 평가한다.
- GATE-01~04는 '명세 후보 확보 / 실측 보류', GATE-05는 시간 원천·산식 미확정, GATE-06과 PRIV 상태는 기존 보류/부분 판정을 유지한다. **통과 게이트 없음, 앱 구현 착수 없음.**
- 이 첨부는 API 명세 미확보 문제를 일부 해결했지만 현재 운영·인증·무료량·실응답을 증명하지 않는다. 추가 키/비용 조건을 확인하지 않고 임의 무인증 호출이나 오래된 API 주소 시험을 하지 않는다.
