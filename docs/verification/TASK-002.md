## 7. 재개에 필요한 최소 입력과 실행 순서

1. **버스 원천부터 확정:** 선택할 공식 서비스 명세 URL, 활용 신청/승인 여부, 무료량·집계기간·현재 남은 예산·초과 시 정책. 무인증 서비스라면 인증 불필요라는 공식 근거를 확인한다. 모든 제주 API가 키를 요구한다고 단정하지 않는다.
2. **필요할 때만 비밀정보 설정:** 해당 API가 인증키를 요구하면 환경 비밀정보 UI에 등록하고 변수명만 전달받는다. 기존 키·앱 설정을 복사/변경하지 않는다. 후보 `JEJU_BUS_API_KEY`는 제안 이름이며 생성하지 않았다. TAGO를 선택하면 서비스별 승인과 키 적용 범위를 확인하고 변수명도 별도로 정한다. 실제 키는 채팅·명령행·문서에 적지 않는다.
3. **정확한 호스트만 허용:** 실제 API 호스트 확정 후 관리 환경 네트워크 정책 확인. 인증 요청·좌표 URL 로그 비노출을 검토한다. 현재 문서 조회 성공을 실행 환경의 API 접속 가능 증거로 간주하지 않는다.
4. **버스 단독 최소 검증:** 조건이 닫히면 TASK-001 전체 13회 상한 안에서 계획을 구체화한다. 공공 ID 조회만으로 검증 가능한 항목은 지도·장소 공급자 선정과 분리할 수 있다. 표본 ID는 공식 표본 또는 선행 응답에서 확보한다. 도시코드 조회 등 새 사전 요청이 필요하면 예산을 먼저 수정·기록하며 자동 증액하지 않는다.
5. **시간·지도 연동은 별도 조건 충족 후:** 지도/장소/도보 무료 자격과 PRIV-004 검토를 닫는다. 필요한 공개 식별자 노출은 사용자 확인 전 도입하지 않는다. FR-019는 계속 제외한다.

환경 인증정보가 없어서 사용자에게 공식 명세·신청/승인 여부·안전하게 설정한 변수명만 요청했다. 사용자가 HWP 명세를 제공하여 분석을 반영했다. 첨부 개요의 무인증 표기와 요청 serviceKey가 상충하므로 키 필요 여부부터 확인해야 한다. 문서 검토 승인만으로 필요한 키나 무료 자격이 생성되지는 않는다. 보류를 해소하지 못한 상태에서 TASK-003으로 진행하거나 MVP를 임의 축소하지 않는다.
