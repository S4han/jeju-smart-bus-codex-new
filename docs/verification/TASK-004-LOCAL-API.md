# TASK-004 — 로컬 실제 도착 조회 연결

확인일: 2026-10-29 (Asia/Seoul). 로컬 개발·검증용이며 운영 배포 아님. 기존 저장소/Vercel 변경 없음.

## 구현과 개인정보 흐름

`ArrivalLookup`의 명시적 버튼 → `src/browser/arrivals.ts` → 동일 출처 `POST /api/arrivals` → Vite 로컬 프록시 → `server/local_api.py` → 제주 BIS 순서다. 자동 조회·폴링·재시도는 없다. 외부 JavaScript 지도 SDK는 로드하지 않는다.

브라우저 요청에는 공개 `stationId` 하나만 넣고 URL 쿼리를 사용하지 않는다. 좌표·검색어·키·쿠키를 보내지 않는다. 서버는 JSON 128 bytes 이내, 정확히 stationId 하나, 공개 스냅샷의 ID만 허용한다. 다른 필드(좌표 포함)·다른 메서드·교차 출처를 거부한다. 서버 요청 로그는 비활성이다. 요청/응답은 no-store, 브라우저는 credentials omit 및 no-referrer를 사용한다. CSP connect-src는 동일 출처만 허용한다.

BIS는 기존 검증에서 키 없는 공개 응답을 확인한 경로만 쓴다. 새 키나 비밀값을 클라이언트에 추가하지 않았다. 도착 응답에 실제 비영 차량이 있는 노선만 최대 3개까지 정차행을 조회한다. 검증하지 못한 노선 행은 표시 대상이 아니다. 한 요청은 외부 최대 4회다. HTTP/서비스/형식 실패 시 재시도하지 않고 배치를 중단한다. 응답당 2 MiB 제한·XML DTD/ENTITY 거부·소켓 timeout 20초를 적용했다. 부분 실패 시 이전 값을 유지하거나 부분 결과를 성공으로 반환하지 않는다.

UI는 요청 중 이전 결과를 숨기고, 정류장 변경·삭제·pagehide·unmount 시 취소/폐기한다. 서버의 진행 중 외부 호출은 브라우저 취소만으로 취소된다고 보장하지 않으므로 승인 예산에서 실제 시도를 차감한다. 60초 만료는 기존 ArrivalPanel이 담당한다. 브라우저 타이머는 외부 조회를 일으키지 않는다.

## 실행과 예산

Python 표준 라이브러리만 사용하므로 새 패키지 의존성은 없다. `npm run api`는 127.0.0.1:8765에만 바인딩하며, 별도로 `npm run dev` 또는 preview를 실행한다. 승인된 검증 예산 SQLite 파일 경로를 서버 환경변수 `JEJU_VERIFICATION_BUDGET_DB`로 지정해야 한다. 파일 부재 시 시작하지 않는다. 파일을 실행할 때마다 생성하거나 카운터를 초기화하지 않는다.

DB에는 used/ceiling/halted 카운터만 있으며 위치·정류장 ID·IP·응답을 저장하지 않는다. SQLite의 배타적 트랜잭션으로 동시 요청의 초과 예약을 막는다. 실패 시 중단 상태를 유지한다. 이것은 승인된 검증 요청의 상한 장치이며 제공기관의 무료량/과금 차단 증명이 아니다. 운영용 예산/호스팅은 별도 검토 대상이다.

이번 승인 파일은 저장소 밖 `/workspace/scratch/task004-research/approved-16-19.sqlite`이며 추가 4/4 소진 상태다. 같은 파일로 다시 실행해도 추가 외부 요청은 차단된다. 이 문서가 카운터 초기화 또는 신규 예산 승인은 아니다.
