# TASK-004 — nrbe HTTP 503 연결 진단

확인일: 2026-10-29 (Asia/Seoul). 대상 새 저장소의 로컬 개발 환경. 관련 FR-004/AC-004, FR-020/AC-020. 판정: 연결 실패 증거 확보, 실제 지도 표시는 여전히 실패/미확인.

## 확인한 사실

추가 SDK 진입이나 지도 타일 재시도 대신 키·좌표 없는 https://nrbe.map.naver.net/ 루트 GET을 1회 실행했다. 응답은 최대 2 KiB만 읽었으며 자동 재시도하지 않았다. SDK/타일/BIS 경로를 요청하지 않았다. 브라우저·앱 CSP 없이도 HTTP 503이 재현됐다.

응답 헤더는 server: envoy, content-type: text/plain이며 본문은 다음과 같다.

> upstream connect error or disconnect/reset before headers. reset reason: remote connection failure

현재 로컬 정책에는 nrbe.map.naver.net이 명시돼 있고 VPN은 미설정이다. 직전 환경 관측은 current/enforced였다. 보존 네트워크 진단 메타데이터 조회 결과 history_status=not_found, records=[]로 추가 원인 로그가 없다. 로그 원문을 읽거나 외부에 전송하지 않았다.

## 해석과 제한

이 루트 요청의 실패는 브라우저 CSP와 관계없이 발생한다. 따라서 추가 호스트 허용이나 CSP 완화만으로 nrbe 503이 해결됐다고 판단할 수 없다. Envoy가 보고한 상위 연결 실패는 확보했지만 어느 계층의 Envoy인지, 원격 서버 장애·중간 프록시·DNS/TLS/연결 설정 중 무엇이 원인인지는 확정되지 않았다. 루트 경로의 응답만으로 타일 경로의 영구 장애를 단정하지 않는다. 이전 실제 검증에서도 nrbe 요청 3건이 503이었으며 그 요청과 이번 루트 요청을 합쳐 SDK 진입 횟수로 세지 않는다.

## 보존 및 다음 단계

원문 URL 쿼리·공개 ID·비밀키·사용자 좌표는 요청/기록하지 않았다. 별도 TASK-004-MAP-NETWORK-DIAGNOSIS.json에 최소 증거를 보존했다. 알려진 SDK 진입 누적 3회, BIS 19/19 소진과 기존 실검증 예약/결과는 변함없다. 루트 진단 1회는 SDK/타일 검증 횟수와 별도다. SDK 요청 수가 제공자 과금 수와 같다는 주장은 하지 않는다.

추가 실제 지도 요청은 잠금 상태다. 새 호스트 등록·같은 ID 재등록·Vercel 변경·직접 연결/프록시 우회·TLS 검증 해제는 하지 않았다. 현재 제공된 환경 도구에는 연결 경로를 수리하거나 진단 수집을 시작하는 기능이 없다. 상위 연결 실패의 원인 증거 또는 환경/제공자 복구 확인 전 동일 검증 반복은 해결책이 아니다. 외부 문의·메일 발송은 하지 않았다.

이번 변경은 증거/문서 추가뿐이며 앱/테스트/빌드 코드는 변경하지 않았다. 전체 테스트·빌드는 반복하지 않았고 기존 통과 결과와 구분한다.


## 환경 진단 도구 후속 확인

현재 네트워크 debug bundle 읽기 도구는 INVALID_ARGUMENT와 함께 environment_diagnostics 보존 기록 도구를 사용하라고 반환했다. 앞서 그 도구의 보존 기록은 not_found였다. 자료 미존재를 네트워크 정상으로 해석하지 않는다. 추가 외부 요청/진단 수집/환경 재설정은 실행하지 않았다.

로컬 변경은 지정 브랜치 feat/task-003-development-foundation에서 커밋으로 보존한다. 원격 push는 수행하지 않는다. 새 환경으로 이동할 때 로컬 커밋이 자동 승계된다고 가정하지 않는다.
