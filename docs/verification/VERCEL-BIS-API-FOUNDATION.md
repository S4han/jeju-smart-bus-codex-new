## 서버 구현과 배포

api/arrivals.py는 Vercel의 Python 표준 라이브러리 Handler 진입점이고 server/hosted_api.py가 입력·원자 예산 계약·응답을 처리한다. Python/Node 패키지 의존성은 추가하지 않았다. 기존 로컬 코드에서 XML 조회/파싱을 fetch_provider_rows로 분리해 로컬 SQLite 예약과 호스팅 공유 장부 계약이 동일한 검증 코드를 사용하도록 했다. 로컬 reserve/database 및 과거 승인/실행 이력은 변경하지 않았다.

기존 /api/* 정적 rewrite를 제거하고 /api/arrivals 실제 함수로 전환한다. 원문 응답/키/위치가 아닌 현재 정류장 ID 허용 목록 및 승인 체크포인트 파일만 함수에 포함한다. Vercel Python 공개 소스 packages/python/src/index.ts의 includeFiles 처리 존재를 확인해 함수 includeFiles에 server/**, 정류장 자료, 승인 JSON을 지정했다. 공식 런타임 소스: https://github.com/vercel/vercel/blob/main/packages/python/src/index.ts (2026-10-29 확인; 계정 비용/실행 결과 확인을 대신하지 않음).

configured_budget_store는 현재 None을 반환한다. 임시 파일/메모리 장부로 대체하지 않는다. 적절한 Origin과 올바른 JSON 요청이 와도 실제 BIS 요청 전에 503 budget_store_unavailable로 종료한다. 화면과 클라이언트의 기존 비활성 경계도 유지해 방문자가 현재 승인 7회를 소비할 수 없다. GET은 405이며 데이터/비밀값이 없는 코드만 반환한다. 모든 API 응답/오류는 no-store, no-referrer다. 원문 요청/응답/좌표 로그를 남기지 않는다.

## 공유 영속 장부 계약

begin_batch(min_used,ceiling)는 최신 승인 사용 체크포인트 이상·정확한 승인 상한·중단 없음·다른 처리 중 배치 없음이 확인돼야 영속적인 단일 소유 배치 표식을 만든다. 새 장부를 0으로 생성하거나 낮은 사용량을 그대로 허용하면 안 된다. 재배포/콜드스타트/TTL로 처리 중 표식을 해제하지 않는다.

각 외부 호출 직전 reserve(batch)가 소유권/상한/중단 상태를 원자 확인하고 사용량을 증가시킨다. 서버 응답을 모두 검증한 뒤 finish_batch로 완료하거나, 실패 시 halt로 영속 중단한다. halt 기록이 실패해도 처리 중 표식이 남아 다음 서버 인스턴스를 막아야 한다. 장애/중단의 모호한 결과를 자동 복구하거나 예산을 되돌리지 않는다. 실제 저장소 어댑터가 이 계약을 구현·검증하기 전에는 연결할 수 없다.

업스트림 작업은 공개 BusArrives 1회 뒤 응답의 운행 차량 노선 StationRoutePr 최대 3회다. 부분 결과·형식 오류·서비스 오류는 성공으로 반환하지 않으며 재시도/폴링하지 않는다. 예산 소진 429, 장부 미연결/장애 503, 제공자 실패 502를 구분한다. 응답은 기존 검증에 필요한 도착 필드만 허용하며 2 MiB 상한이다. 클라이언트 신선도/매핑 검증도 계속 필요하다.

## 검증과 한계

Python unittest 16개 통과(기존 6개+호스팅 10개). 임시 합성 SQLite 어댑터로 동시 인스턴스가 남은 7회를 넘기지 않음, 새 인스턴스 사용량/중단 보존, 실패 중단 쓰기 장애 뒤 처리 중 표식으로 다음 요청 차단, 초기화된 장부/승인 외 상한 거부를 검사했다. 실제 API Handler를 로컬 HTTP로 호출해 503 및 no-store/no-referrer를 확인했다. 합성 SQLite는 테스트 어댑터이고 Vercel에 연결하지 않았다.

Vitest 155개+Node guard 3개, 타입/빌드/클라이언트 비밀값 검사 및 배포 지도 모의 검증 통과. 실제 장부를 다시 읽어 23/30회 그대로임을 확인했다. Vercel 실제 런타임 API 응답은 아직 원격 실측하지 않았다. GitHub의 Vercel 빌드/배포 상태와 API 실행 성공은 구분한다.

현재 도구/환경에서 연결 가능한 공유 영속 저장소나 그 자격은 확인되지 않았다. Vercel 계정의 실제 DB 유무는 읽을 수 없어 사용자에게 새 프로젝트 전용 저장소가 있는지 질문했다. 기존 두 프로젝트의 저장소/키/도메인은 재사용하지 않는다. AGENTS.md의 데이터 저장소 암묵 도입 금지에 따라 계정·무료 조건·서비스 선택을 임의 확정하지 않았다. 다음 작업은 전용 저장소 선택/연결과 실제 어댑터 검증이다. 전체 TASK-004 완료 또는 공개 BIS 활성화를 선언하지 않는다.
