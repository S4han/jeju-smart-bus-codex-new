# Vercel BIS 조회 연결의 다음 단계

2026-10-29 (Asia/Seoul). 준비 설계이며 새 저장소/서비스를 만들거나 실제 Vercel 조회 API를 활성화한 기록이 아니다. TASK-004 FR-005/AC-005 및 검증 예산 보호 범위다.

## 현재 확인

현재 공개 BIS 표본은 2026-10-29 16:31 KST에 추가 4회로 조회했고, 누적 23/30회·잔여 7회다. 로컬 SQLite는 요청 직전 BEGIN IMMEDIATE로 예약하므로 이 실행 환경에서는 초과 호출을 막는다. Vercel은 정적 앱과 비활성 API 안내만 배포 중이다. 이미 받은 도착 응답은 60초 기준으로 만료되므로 정적 배포로 재사용하면 실시간 정보가 되지 않는다.

## 연결에 필요한 계약

- POST /api/arrivals는 현재 검증된 공개 stationId 하나만 받는다. 좌표/검색어/키/쿠키를 받거나 로그로 남기지 않는다. 동일 출처 검증, 128-byte 입력 한도, 응답/오류 no-store를 유지한다.
- 외부 요청 하나마다 **공유 영속 장부**에서 used<ceiling 및 halted=false를 원자적으로 확인하고 used를 먼저 올린다. 초기값은 최신 실제 소비 기록을 반영한다. 현재 기준은 used=23, ceiling=30이며 이후 소비가 있으면 그 수치를 사용한다. 재배포/콜드스타트가 카운터를 만들거나 초기화하지 않는다.
- 외부 요청은 기존 BusArrives 1회 뒤 실제 비영 차량 노선의 StationRoutePr 최대 3회다. 실패/서비스 오류/형식 오류는 halted로 영속 기록하고 재시도·폴링하지 않는다. 부분 실패를 성공으로 반환하지 않는다.
- 장부/인증 설정이 없거나 장부 서비스에 장애가 생기면 BIS 요청 전 503으로 중단한다. 예산 소진 시 429를 반환한다. 인스턴스 메모리·Vercel 임시 파일·서명 토큰만으로 전역 사용량을 제한했다고 판단하지 않는다.
- 실제 도착행은 기존 매핑·차량·순서·방향·60초 검증을 통과한 것만 표시하고 TTL 이후 제거한다. 서버에 사용자 위치를 저장하지 않는다.

## 필요한 결정과 검증

먼저 새 프로젝트 전용으로 사용할 영속 저장소/실행 호스트를 정해야 한다. 기존 두 프로젝트의 저장소/키/설정을 재사용하지 않는다. 현재 연결된 영속 예산 저장소는 없으며 계정·무료 조건·요금 및 초과 차단은 미확인이다. AGENTS.md의 데이터 저장소를 암묵적으로 도입하지 않는 규칙에 따라 새 서비스를 만들거나 의존성을 추가하지 않았다.

구현 시 합성 장부로 동시 요청 상한·콜드스타트/재배포 사용량 보존·저장소 오류의 fail-closed·실패 중단 보존을 먼저 검사한다. 이후 남은 승인 예산 안에서 한정된 실제 검증을 실행한다. 저장소의 실제 무료 조건/접속 설정 없이 공개 조회 버튼부터 활성화하지 않는다. 이 문서는 서비스 선택/비용 승인 또는 전체 TASK-004 완료를 대신하지 않는다.


## 구현 진행

서버 경계와 공유 장부의 배치/예약/완료/중단 계약, 테스트 및 Vercel 함수 진입점을 구현했다. 실제 저장소 어댑터는 미연결이므로 BIS 요청은 503으로 중단한다. 최신 범위는 [API 기반 기록](VERCEL-BIS-API-FOUNDATION.md)을 따른다. 새 서비스를 만들거나 임시 장부로 우회하지 않았다.
